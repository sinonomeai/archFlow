# 4\. 会话 Conversations

## 4\.1 创建会话



```HTTP
POST /api/v1/projects/:projectId/conversations
```



**请求体**：



```JSON
{ "title": "新会话", "initialAssetId": "ast_1" }
```



|字段|必填|说明|
|---|---|---|
|`title`|否|默认 `"新会话"`，长度见 Zod（`CreateConversationInput`）。**默认值由服务端兜底**|
|`initialAssetId`|否|基于已有资产开新会话。**服务端必须校验该资产属于 ****`projectId`**，否则 404|



**响应 ****`201 Created`**：



```JSON
{
  "id": "cnv_1",
  "projectId": "prj_1",
  "title": "新会话",
  "draftGraph": null,
  "draftVersion": 0,
  "messageCount": 0,
  "lastMessage": null,
  "createdAt": "2026-11-08T16:50:30+08:00",
  "updatedAt": "2026-11-08T16:50:30+08:00"
}
```



## 4\.2 获取会话详情



```HTTP
GET /api/v1/conversations/:conversationId
```



**描述**：**只返回会话元信息 \+ 草稿图，不再返回全部消息**（消息走 4\.4 分页）。



**响应 ****`200 OK`**：



```JSON
{
  "id": "cnv_1",
  "projectId": "prj_1",
  "title": "订单服务拆分",
  "draftGraph": { "nodes": [], "edges": [] },
  "draftVersion": 12,
  "messageCount": 48,
  "lastMessage": {
    "id": "msg_48",
    "role": "assistant",
    "contentPreview": "建议按领域拆成三个服务……",
    "createdAt": "2026-11-08T16:40:00+08:00"
  },
  "createdAt": "2026-11-01T10:00:00+08:00",
  "updatedAt": "2026-11-08T16:40:00+08:00"
}
```



|字段|说明|
|---|---|
|`draftVersion`|草稿版本号，用于 4\.3 的乐观锁|



## 4\.3 保存草稿图



```HTTP
PUT /api/v1/conversations/:conversationId/draft
```



> **为什么是 ****`PUT`**** 不是 ****`PATCH`**：这里语义是**全量替换整张图**，`PATCH` 表示部分字段更新，语义不符。
> 
> 



**请求体**：



```JSON
{ "graph": { "nodes": [], "edges": [] }, "baseVersion": 12 }
```



|字段|必填|说明|
|---|---|---|
|`graph`|是|全量图；大小与嵌套深度见 `GraphInput`|
|`baseVersion`|是|客户端当前持有的 `draftVersion`，用于**乐观锁**|



**响应 ****`200 OK`**：



```JSON
{ "draftVersion": 13, "updatedAt": "2026-11-08T16:51:00+08:00" }
```



**错误**：



|HTTP|code|说明|
|---|---|---|
|409|`DRAFT_VERSION_CONFLICT`<br>|版本冲突（多标签页同时编辑），`data.currentVersion` 给服务端最新版本，前端提示「已在其他窗口修改」|
|413|`GRAPH_TOO_LARGE`|图序列化超过 `GRAPH_MAX_BYTES`|
|422|`GRAPH_INVALID`|图结构非法（`nodes` / `edges` 非数组、嵌套过深）|



> **并发保护**：没有 `baseVersion` 就会两个标签页互相覆盖。**必须用乐观锁**，不要用「最后写入胜出」。
> 
> 
> 
> **限流建议**（待定项）：前端停手 3 秒后写入；服务端对单会话建议 ≤ 2 次/秒，超出返回 `429`。
> 
>

**`metadata`**** 为可空对象**，内部字段均可选：

## 4\.7 基于历史消息分叉



```HTTP
POST /api/v1/conversations/:conversationId/fork
Idempotency-Key: <uuid>
```



**请求体**：



```JSON
{ "sourceMessageId": "msg_20" }
```



**响应 ****`201 Created`**：



```JSON
{
  "id": "cnv_2",
  "projectId": "prj_1",
  "title": "订单服务拆分（分叉）",
  "draftGraph": { "nodes": [], "edges": [] },
  "draftVersion": 0,
  "messageCount": 21,
  "lastMessage": {
    "id": "msg_20",
    "role": "user",
    "contentPreview": "那消息队列怎么选？",
    "createdAt": "2026-11-08T17:00:00+08:00"
  },
  "createdAt": "2026-11-08T17:00:00+08:00",
  "updatedAt": "2026-11-08T17:00:00+08:00",
  "forkedFrom": { "conversationId": "cnv_1", "sourceMessageId": "msg_20" }
}
```



**语义约定**：



- 复制 `sourceMessageId` **及其之前**的全部消息到新会话（含各自的 `graphSnapshot`）。

- 新会话**独立**：后续在原会话继续对话，新会话不受影响。

- `sourceMessageId` 不属于该会话 → `404` / `MESSAGE_NOT_FOUND`。

- **重复点击**由 `Idempotency-Key` 兜住，不会生成多个会话。

    

> **成本提示**：物理复制长会话会写放大。建议加保护：`messageCount > 200` 时返回 `422`，或改为「引用式分叉」（新会话只存指针，读时合并）。v1 先用物理复制 \+ 上限，简单可靠。

## 4\.8 画布布局

> 2026-11-13 新增。布局与语义图分离：`current_draft_graph` 只存节点/边，坐标存本接口。

### 4\.8.1 获取布局

```HTTP
GET /api/v1/conversations/:conversationId/layout
```

**响应 `200 OK`**：

```JSON
{
  "layout": { "nodes": { "n1": { "x": 120, "y": 80 } } },
  "version": 3,
  "updatedAt": "2026-11-13T19:00:00+08:00"
}
```

没有保存过布局时返回 `{ "nodes": {} }`、`version: 0`。

### 4\.8.2 保存布局

```HTTP
PUT /api/v1/conversations/:conversationId/layout
```

**请求体**：

```JSON
{
  "layout": { "nodes": { "n1": { "x": 120, "y": 80 } } },
  "baseVersion": 3
}
```

**响应 `200 OK`**：同 4.8.1，`version` 自增。

**错误**：

|HTTP|code|说明|
|---|---|---|
|409|`DRAFT_VERSION_CONFLICT`|`baseVersion` 与服务端不一致，`data.currentVersion` 给最新版本|
|404|`CONVERSATION_NOT_FOUND`|会话不存在或不属于当前用户|

> 首次保存传 `baseVersion: 0`。该版本号独立于会话草稿的 `draftVersion`。

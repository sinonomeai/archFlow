## 0. 当前状态

**已具备**

- 数据库：业务实体、画布布局表与迁移已在上游主链路使用；新增 `SingleActiveRun` 迁移文件暂未注册或启用，现有正式 run 不具备该迁移的数据库单活跃约束，激活前需验证并发和历史数据兼容性。
- 正式 API：已接认证、项目、会话、文件、RAG、资产、运行、SSE 与系统模块，使用 PostgreSQL / Redis / MinIO；上游有本地端到端记录，合并后的回归尚待验证。
- 契约：common / auth / project / knowledge / asset / conversation / agent / sse / system / mock 已导出；运行态、HITL 中断与图结构已在 P0-01 / P0-13 定稿。
- 默认 Web 使用正式 `/api/v1`，已实现项目/会话、画布布局保存、资产、分支和原有 SSE/约束卡片流程。设置 `apps/web/.env.local` 的 `MOCK_API=1` 则可在同一工作台路径使用隔离的 `/api/mock` 文件数据与运行入口；`ARCHFLOW_PREVIEW_AGENT=1` 可选真实模型驱动。
- 新 `packages/agent` 路由实现包含整句规则、可选意图样例匹配、LLM 判断、直达与有界计划、澄清恢复和图补丁。新 `AgentRunService` 具备 TypeORM 持久化实现与隔离数据库测试，但尚未替换上游正式 `RunModule` 及其 HTTP/SSE 路径；此前测试记录仅证明各自分支上的行为。
- 文档：`mvp.md`、`数据流.md`、`API文档/`、`表设计.md`、`架构规划.md`、P0 实施记录。

**主要缺口**

- 将新编排和持久化服务接入已有真实运行入口，并复核原有鉴权、SSE 恢复、卡片、图提交和项目检索行为；新迁移需验证与现有 schema 及数据兼容。
- 上游文本入库/RAG 已实现；新编排的项目资料查询尚未接入预览，真实模型效果和合并后的正式环境联调待验收。图片解析仍是 P1-04。
- 正式画布布局拖拽保存、资产、快照和 fork 已有上游实现；新图补丁与历史图引用尚未进入真实客户端工作流。

> 证据：迁移、API 启动与 404 外壳见 [后端 P0 基础设施落地](./问题记录/2026-11-11-后端P0基础设施落地.md)。

## 1. 优先级定义

- **P0**：阻塞 MVP 主链路；不做就无法端到端跑通。
- **P1**：不阻塞主链路，但直接影响质量、安全或可评估性。
- **P2**：post-MVP 扩展；有明确触发条件再做。

## 8. 完成定义

一项任务标记 `✅` 前，至少满足：

1. 契约先改 `packages/shared`，类型检查通过；涉及数据库的补迁移。
2. 有对应测试或可复现的验收步骤（写清命令），不能只写“已实现”。
3. 错误路径有明确返回码，不泄露堆栈 / SQL / 内部路径。
4. 关键路径有 traceId 和日志。
5. 文档中的契约与代码一致；行为变了就同步 `API文档` / `表设计` / `数据流`。
6. Mock 仅用于独立预览；正式接入和合并后的完成状态以真实 `/api/v1` 验证为准。

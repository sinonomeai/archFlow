#  ArchFlow MVP (最小可行性产品) 需求边界

## 一、 MVP 核心目标

跑通“输入 Idea → AI 追问约束 → 生成架构图 → 用户微调 → 保存为资产”的端到端单机闭环。
**产品边界：** 每个项目只有一个所有者。多人协作已退出产品路线，不安排项目共享、成员邀请、项目角色或实时共同编辑。草稿版本检查和历史分支仍保留。

------

## 二、  MVP 必须包含的功能 (Must Have)

### 1. 用户认证 (Auth)

- 支持邮箱 + 密码注册与登录。
- 基于 Redis 的双 Token (Access + Refresh) 无感刷新机制。
- 登录状态失效时，前端能自动拦截并跳转回登录页。

### 2. 侧边栏与项目管理 (Sidebar & Projects)

- 支持“新建项目”并在左侧树形菜单中展示。
- 空状态处理：当用户没有任何项目时，主界面显示全屏引导页，而不是空白的三栏布局。
- 支持展示历史会话列表，并高亮当前选中的会话。

### 3. AI 对话与约束收集 (Agent Chat)

- **统一对话**。用户在一个聊天框提需求。服务端按整句规则、意图样例匹配、LLM 判断选择直接执行或有界计划。需要澄清时暂停这一轮，回答后继续。
- 支持原生 SSE 流式输出（打字机效果）。
- **约束卡片**：AI 能抛出结构化的单选/多选卡片（如团队规模），用户作答后卡片原地变灰，Agent 继续推理。
- **状态提示**：AI 思考过程中，能展示“正在查知识库”、“正在生成图”等阶段性提示。

### 4. 架构图画布 (React Flow Canvas)

- 支持渲染大模型返回的节点和连线。
- 支持用户手动拖拽节点、缩放画布。
- 支持点击“自动布局”，使用 Dagre 算法瞬间重排节点。
- **防抖保存与乐观锁**：用户拖拽停顿 3 秒后自动保存草稿。如果同一账号在两个标签页编辑，或助手改图期间用户保存了新版，版本号检查会阻止旧草稿覆盖新版。

### 5. 知识库检索 (Basic RAG)

- 支持上传并解析 `.md` / `.txt` 文本与图片。
- PDF / DOCX 仅上传存储、不解析，不可被 AI 引用。
- 文件存放在 MinIO，文本内容被切片存入 PostgreSQL (`pgvector`)。
- AI 对话时，能基于已解析（`ready`）的文件内容进行回答。

### 6. 资产固化与历史回溯 (Assets & Fork)

- **保存资产**：将满意的画布保存为“架构资产”，存入侧边栏。
- **恢复快照**：点击历史消息的“恢复快照”，右侧画布瞬间回到当时的版本。
- **物理复制分支**：基于某条历史消息“开启新对话”，系统复制该消息及之前的记录，保证上下文绝对隔离。

------

## 三、  MVP 明确不做的功能 (Won't Have)

为了防止技术发散，以下功能**严禁**在 MVP 代码库中出现：

1. **PDF / DOCX 解析**：只上传存储，不做解析（避免引入 Python/Go 或重型解析库）。
2. **复杂的文档解析微服务**：所有文本切片逻辑用 Node.js 原地解决，不引入 Python/Go 微服务。
3. **异步消息队列**：不使用 BullMQ / RabbitMQ。大模型推流直接用 Node.js 异步长连接处理。
4. **Agent 框架**。采用透明的原生 SDK、结构化输出和手写编排。开放式多 Agent 协作与工具插件市场留在后续评估范围。
5. **移动端深度适配**：优先保证桌面端宽屏（Web）体验。

> post-MVP 的 RabbitMQ + Go 文档解析服务规划见 [`架构规划.md`](./架构规划.md)；不改变本文的 MVP 边界，也不意味着现在可以写相关代码。

------

## 四、验收标准

正式服务验证后填写下列验收项。本地 AC1、AC2 演示步骤与记录入口见 [接手说明](Agent架构讨论交接.md#5-本地体验与正式验收)。可按需通过 [待做清单](待做清单.md) 查询相关任务。

### AC1 注册、登录和创建项目

- [ ] 注册并登录一个没有项目的账号，看到引导页。创建项目和会话后刷新页面，仍能从项目树打开该会话。

### AC2 流式回答、追问和重连

- [ ] 在正式聊天入口提问。界面先显示适用的阶段提示，回答文字在任务结束前随模型生成逐段出现。
- [ ] 发送一条信息不足的请求，看到带选项的追问卡片。选一项回答，卡片显示已回答，原 run 继续执行；当前正式服务会在回答消息之后新建一条助手消息，预览会复用原助手消息。合并后需统一并验收这一交互。
- [ ] 生成中断网并重连。缓冲可用时从断点补发，缓冲失效时从服务端取回已保存的文字和任务状态。两种情况下都沿用同一次任务，文字只显示一遍。
- [ ] 先生成两个架构图版本，再在缓冲失效后查看第一轮任务。第一轮回答对应第一轮保存的架构图，当前画布保留最新草稿。
- [ ] 生成中取消。界面显示已取消，原来保存的草稿仍可打开，用户可以再次发送请求。
- [ ] 在验收环境中重启正在处理任务的后端。被打断的执行显示为失败，已保存的文字和草稿仍可读取。用户可以重试，会话能接受新请求。

### AC3 生成、解释和修改架构图

- [ ] 回答「给什么系统画图」后，原任务继续生成。架构图检查并保存成功后，右侧画布显示完整的节点和连线。
- [ ] 保存过两版架构图后，明确指定其中一版，请助手只解释。回答对应指定版本，当前草稿保持原样。如果无法确认你说的是哪张图，助手先追问。
- [ ] 对当前画布说「按项目缓存规范修改商品查询，订单链路保持原样，再解释改完的流程」。系统先找到规范，再在临时副本上改图，解释修改后的商品查询。全部完成后，画布一次更新，订单链路保持原样。
- [ ] 用测试模型让解释步骤第一次超时，并为重试留出时间。助手沿用刚改好的架构图重试解释，成功后只保存一次草稿。
- [ ] 使用找不到的规范再试一次，或让改图步骤失败。界面说明卡在哪一步，依赖新版的解释标为未完成，原草稿仍然可用。

### AC4 调整画布、保存和刷新

- [ ] 拖拽节点并等草稿保存。刷新后，节点仍在最后保存的位置。使用「自动布局」重新摆放后，也能保存并恢复调整后的布局。
- [ ] 在两个标签页分别修改同一份草稿。一个标签页先保存，另一页随后保存时收到版本冲突提示，服务端保留先保存的新版。
- [ ] 在助手执行改图期间手动保存新版。助手结束时提示版本冲突，画布保留手动保存的新版，可以基于它重试。

### AC5 保存为项目资产

- [ ] 在满意的画布上点「保存为资产」。新资产立即出现在当前项目侧栏，刷新后仍可打开，看到保存时的架构图。

### AC6 恢复历史版本和开启新会话

- [ ] 从旧消息点「恢复快照」，当前画布还原为该消息保存的架构图，原来各条历史消息仍可查看。
- [ ] 从旧消息开启新会话。新会话带有所选消息及之前的对话和当时的架构图。分别编辑两个会话，各自的草稿独立保存。

### AC7 根据项目资料回答

- [ ] 分别上传 `.md` 和 `.txt`。解析完成后提问，回答中的引用能对应命中的原文。
- [ ] 上传一张支持解析的图片，确认可以看到解析完成的状态。
- [ ] 指定缺失、仍在处理或解析失败的资料提问，界面说明暂时没有可用依据。上传 PDF 和 DOCX 后，文件状态显示仅存储。明确要求依据其中一份回答时，助手说明该文件没有可引用的解析结果。
- [ ] 把某份规范只上传到另一个项目，再在当前项目要求依据该规范回答。助手说明当前项目找不到该资料，引用只来自当前项目。

图片解析结果的入库和引用按[待做清单](待做清单.md)的 `P1-04` 单独验收。
